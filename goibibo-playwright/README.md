# Goibibo Playwright Automation Framework

**Aperture Enterprises — Client A (goibibo.com) | Selenium Certification Project**

> Hybrid Test Automation Framework: Playwright + TypeScript + Page Object Model + Excel Data-Driven + Custom Extent Reports + GitHub Actions CI/CD

---

## Technology Stack

| Tool | Purpose |
|------|---------|
| **Playwright v1.44** | Browser automation (replaces Selenium WebDriver) |
| **TypeScript 5.4** | Strongly-typed test code |
| **Page Object Model** | Maintainable UI abstraction |
| **xlsx** | Excel data-driven testing (replaces TestNG @DataProvider) |
| **Custom ExtentReporter** | Self-contained HTML report (Extent Reports style) |
| **JUnit XML** | TestNG-compatible XML for CI/CD integration |
| **GitHub Actions** | CI/CD pipeline: Lint → Chrome → Firefox → Reports |
| **VS Code** | Debugging with 5 launch configurations |

## Quick Start

### Prerequisites
- **Node.js 18+** — [nodejs.org](https://nodejs.org)
- **VS Code** with **Playwright Test** extension (`ms-playwright.playwright`)

### 1. Install dependencies

```bash
cd goibibo-playwright
npm install
npx playwright install --with-deps
```

### 2. Generate Excel test data

```bash
npx ts-node src/utils/createTestData.ts
```

This creates `test-data/TestData.xlsx` with 3 sheets and sample rows.  
The `pretest` hook runs this automatically before every `npm test`.

### 3. Run tests

```bash
# All 4 scenarios on both browsers
npm test

# Watch the browser (headed mode)
npm run test:headed

# Chrome only
npm run test:chrome

# Firefox only
npm run test:firefox

# Individual scenarios
npm run test:scenario1    # Scenario 1: Search hotel + log name
npm run test:scenario2    # Scenario 2: Book with dummy card
npm run test:scenario3    # Scenario 3: Hotel detail tabs
npm run test:scenario4    # Scenario 4: Apply + verify filters
```

### 4. View reports

```bash
# Playwright HTML report (full trace + video)
npm run report

# Extent-style HTML report (open in browser)
open reports/extent-report.html

# JUnit XML (for CI/Jira import)
cat reports/results.xml
```

## Test Scenarios

### Scenario 1 — Search Hotel & Log Name
**File:** `src/tests/searchHotel.spec.ts`

1. Open `https://www.goibibo.com/`
2. Click **Hotels** menu
3. Enter location (from Excel: Ooty, Munnar, Coorg)
4. Set check-in / check-out dates
5. Select **1 adult** under Rooms
6. Click **Get Set Go**
7. Log hotel title + total count → TestNG/Extent report

### Scenario 2 — Book Hotel with Dummy Card
**File:** `src/tests/bookHotel.spec.ts`

1. Search hotels in **Ooty** (stay ≥ 2 nights)
2. Log hotel name + count
3. Verify hotel title → click it
4. On detail page: verify name → click **Book Now**
5. Verify booking details
6. Fill guest details → click Pay
7. Enter **dummy card** (4111111111111111)
8. Observe and assert the **error message**

### Scenario 3 — Hotel Detail Tabs
**File:** `src/tests/hotelDetails.spec.ts`

1. Search + click first hotel
2. Click **Room & Rates** tab → log room image URL
3. Click **Location** tab → verify section rendered
4. Click **Guest Reviews** tab → verify Ratings & Reviews visible
5. Click **Questions & Answers** tab → verify Q&A section
6. Click **Hotel Policies** tab → verify policies text

### Scenario 4 — Filters
**File:** `src/tests/filterHotel.spec.ts`

1. Search hotels in Ooty
2. Record count **before** filters
3. Apply **Pay At Hotel** filter
4. Apply **Rating = 4** filter
5. Apply **first price range** filter
6. Verify each filter is checked
7. Assert count ≤ initial count (filters narrow results)

## Test Data (Excel)

`test-data/TestData.xlsx` has 3 sheets:

| Sheet | Scenarios | Key Columns |
|-------|-----------|-------------|
| **HotelSearch** | 1, 3 | Location, CheckInOffset, CheckOutOffset, Adults, Description |
| **BookHotel** | 2 | All HotelSearch cols + GuestFirstName/Email/Phone + Card details |
| **HotelFilter** | 4 | Location, PayAtHotel, Rating, PriceRangeIndex |

**To add more test cases:** add rows to any sheet. The tests loop automatically.

**Offsets:** `CheckInOffset=7` means check-in = today + 7 days. Dates are always future-safe.

## Reporting

### Extent Report (Custom)
- **Path:** `reports/extent-report.html`
- Dashboard: total / pass / fail / skip + pass-rate bar
- Per-test: step logs, error messages, inline screenshots (base64)
- Self-contained single HTML file — no server needed

### Playwright HTML Report
- **Path:** `reports/playwright-html/index.html`
- Full Playwright trace viewer
- Video replay on failure
- `npx playwright show-report reports/playwright-html`

### JUnit XML (TestNG-compatible)
- **Path:** `reports/results.xml`
- Importable into: Jira Zephyr, Azure DevOps, Jenkins
- Same format as TestNG `testng-results.xml`

### Logger (TestNG Reporter.log equivalent)
```typescript
report.pass(`Hotel Name (first result): ${firstName}`);
report.info(`Total Hotels Found: ${totalCount}`);
report.warn("Location section map failed to load");
```
All messages attach to the Playwright report as named annotations.

## CI/CD — GitHub Actions

Pipeline file: `.github/workflows/playwright.yml`

```
push/PR to main/develop
        ↓
  Lint & Type Check (tsc --noEmit)
        ↓
  ┌──────────────────┬──────────────────┐
  │  Test: Chromium  │  Test: Firefox   │
  │  4 scenarios     │  4 scenarios     │
  └──────────────────┴──────────────────┘
        ↓
  Publish Reports (HTML + JUnit XML artifacts, 14-day retention)
```

**Artifacts uploaded per run:**
- `playwright-report-chromium` / `playwright-report-firefox`
- `junit-results-chromium` / `junit-results-firefox`
- `test-results-*` (screenshots & videos on failure)

**Manual trigger:** Go to GitHub Actions → Run workflow → choose browser + headless mode.

## VS Code Debugging

Open **Run & Debug** (`Ctrl+Shift+D`) and pick a config:

| Config | What it runs |
|--------|-------------|
| Debug — All Tests | All 4 scenarios, headed, no timeout |
| Debug — Scenario 1: Search Hotel | `searchHotel.spec.ts` |
| Debug — Scenario 2: Book Hotel | `bookHotel.spec.ts` |
| Debug — Scenario 3: Hotel Details | `hotelDetails.spec.ts` |
| Debug — Scenario 4: Filters | `filterHotel.spec.ts` |

All configs use `--headed` + `--timeout=0` (Playwright Inspector compatible).

Set breakpoints in `.spec.ts` or page object files, then press **F5**.

## Environment Variables

| Variable | Default | Description |
|----------|---------|-------------|
| `BASE_URL` | `https://www.goibibo.com` | Target URL |
| `HEADLESS` | `true` | Set `false` to watch browser |
| `EXCEL_FILE_PATH` | `./test-data/TestData.xlsx` | Data file path |
| `GUEST_FIRST_NAME` | `Ram` | Guest name (Scenario 2) |
| `GUEST_EMAIL` | `ram.dummy@gmail.com` | Guest email |
| `CARD_NUMBER` | `4111111111111111` | Dummy card (triggers error) |

Copy `.env` to `.env.local` and override as needed. Never commit real card numbers.
